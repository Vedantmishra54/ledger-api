# Assumptions

1. Account and transaction ids are UUIDs generated by the database.
2. A `balance` field sent when creating an account is ignored (balance always starts at 0).
3. Money uses `NUMERIC(14,2)`: max 2 decimal places, amount must be a JSON number (not a string), max 1,000,000,000.
4. `reference_id` is a non-empty string up to 100 chars, unique per account (not globally).
5. A duplicate `reference_id` returns `409` with the original transaction in `error.details`; nothing changes.
6. Insufficient balance returns `422`; malformed input returns `400`; unknown account returns `404`.
7. History default `limit` is 10, max 100; `page` starts at 1. Ties on `created_at` are broken by `id`.
8. Transfers create two ledger rows (a debit on the source, a credit on the destination) that share the same `reference_id`; the reference must be unused on BOTH accounts. Source and destination must differ.
9. No authentication/authorization (out of scope for this assignment).
10. Transactions are immutable: no update/delete endpoints, plus a DB trigger as a second safety net.
11. Account deletion is not supported.
